# AGENTS.md

## Mapa y arranque
- Two independent apps, no root workspace: `backend/` (Express 5 + `pg`, raw SQL, CommonJS) and `frontend/` (React 19 + Vite 8 + Tailwind v4). The backend never serves the SPA: in dev Vite proxies `/api` → `localhost:3000`; `frontend/dist/` is build output only.
- Run the backend **from `backend/`**: `dotenv.config()` resolves `.env` from cwd. `backend/.env` is tracked (`DB_NAME=sistemapostulantes`); `.env.example` and `src/config/db.js` fall back to `postulantes_v2`, so a missing/unread `.env` silently targets the wrong DB. Frontend has no `.env` (only `.env.example`); `lib/api.js` falls back to `''` so the browser calls `/api` on its own origin.
- No CI, hooks or root package; nothing auto-verifies changes. Root `generar_documentacion.py` needs `python-docx`; root `.docx`/`.html`/`.png` are academic deliverables. `docs/superpowers/plans/` and `.superpowers/sdd/` hold the **completed** public-site redesign plan/ledger, not live architecture docs. `frontend/README.md` is stock Vite boilerplate.
- `Silver parasoul inc/` (old static corporate site) is tracked but **deleted in this working tree** — don't restore it; its design now lives in `frontend/public/*.css` + `PublicoCorporativo`.
- Root dev scripts (currently untracked): `iniciar.bat` → `node dev-runner.cjs` starts backend then frontend 2.5 s later; `detener.bat` kills whatever listens on ports 3000/5173. Both are currently untracked. The SSE + admin-technology work is also uncommitted — check `git status` before assuming HEAD behavior.


```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d sistemapostulantes -f backend/sql/final/esquema_final.sql
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d sistemapostulantes -f backend/sql/final/datos_final.sql
```
  `esquema_final.sql` starts with `DROP ... CASCADE` (wipes everything); `sql/historial/` is evidence only, never execute it. `datos_final.sql` starts with `TRUNCATE ... RESTART IDENTITY CASCADE` and ends in `COMMIT`, so it is safe to reload.
- Integration tests need the server running **and** the seed loaded; `tests/kpiConv.test.js` is pure unit. One file: `node --test tests/convocatorias.test.js`; one test: add `--test-name-pattern="texto del test"`; retarget with `API_URL=http://host:port`. The suite mutates the DB (rewrites `postulante04`, appends events, hires people, leaves test users), so reload the seed afterwards and never point it at a real DB.
- `realtime.test.js` is **not** in `npm test`: it self-hosts the app on a random port, needs the DB, creates and deletes one test user, and calls `pool.end()` — run it alone. It uses fixed `setTimeout(400)` waits, so timing failures are possible.
- `npm run lint` exits 0 with 0 warnings and 0 errors; `.oxlintrc.json` makes `react/rules-of-hooks` an error. `npm run build` passes. Backend has no lint/typecheck.
- Both servers print the LAN addresses other PCs must use; Vite prints the `Postulantes` (`/`) and `Sistema interno` (`/interno/login`) links with its actual port. Never hardcode a LAN IP.

## Backend: non-obvious rules
- Flow is `routes → controller → service → model (SQL only) → JSON`. `src/domain/catalogos.js` is the single source of truth for roles, states, transitions, levels/factors and KPI keys; the frontend reads them from `GET /api/catalogos` (which **requires** a token). Role gates live only in `routes/index.js`; row-level scoping (`exigirDueno`, `creada_por`) lives in controllers.
- **No existe la postulación**: the postulante edits his profile (`PUT /yo`) and a live list is built from it. The old `postular`/`mis-postulaciones`/`postulaciones/:id/estado` routes are 404.
- Padrón = personas without account or with `postulante` + `estado_cuenta='activa'`, and `disponibilidad <> 'Contratado'` (staff and pending accounts excluded). Cached 60 s in `services/candidatos.js`, invalidated via `Candidatos.invalidarPadron()` on profile/person/account changes, technology CRUD and hire. Clean seed: **50**.
- `convocatorias.tipo` is a closed catalog (`Pasantía|Momentáneo|Mensual|De planta`; outside → 400). `kpi_minimo` (0–100, default 25) is a listing threshold, not a hard filter: below it the person appears in `excluidos[]` with `motivo_exclusion`. `cupos` (default 1) are vacancies; hiring the last one closes the convocatoria in the same transaction (`SELECT ... FOR UPDATE`, `cierre_automatico: true`). `cerrada`/`rechazada` is read-only (409); `PATCH /:id` only works while `pendiente`/`abierta` (admin any, reclutador own → 403 otherwise).
- Pipeline rows live in `candidatos_convocatoria`; staff creates them by **tomando** a candidate (UPSERT) and snapshots (`kpi_al_tomar`, `match_pct`, `kpi_perfil`) freeze on first take. Transitions: `postulado→consulta|descartado`, `consulta→preseleccionado|descartado`, `preseleccionado→contratado|descartado`, `descartado→consulta`; `contratado` is terminal. Invalid → 409, same state → no-op. `mover` validates, locks the row, enforces cupos, appends `eventos_postulacion` (bitácora only) and runs in `conTransaccion`.
- `contratado` is per convocatoria: that ranking skips the row (it goes to `contratados_detalle[]`), other convocatorias still show the person. But hiring also sets `personas.disponibilidad='Contratado'`, removing her from **all** padrons until she saves another availability in `MiPerfil`. `GET /api/mis-convocatorias` then reports `califica:false`, `posicion:null`, «Ya estás contratado en esta convocatoria».
- Only routes without `autenticar` middleware: `/api/health`, `/api/auth/registro`, `/api/auth/login`, `/api/tecnologias`, `/api/publico/convocatorias`, and `/api/realtime` (SSE: it verifies the JWT itself from `?token=` or Bearer, `JWT_SECRET || 'dev'`). The public listing returns only `abierta` with `id, titulo, tipo, anios_min, disponibilidad, cupos, vacantes, requisitos[]` (optional ones suffixed ` (deseable)`) — no `kpi_minimo`, correos or internal counts.
- Realtime is in-memory SSE (`services/eventosRealtime.js`, no persistence/replay): `POSTULANTE_REGISTRADO`→admin, `CUENTA_APROBADA`→usuarioId (includes `nuevoToken` with `estado_cuenta:'activa'`), `CUENTA_RECHAZADA`/`CUENTA_ELIMINADA`→admin/usuario, `CUENTA_ACTUALIZADA`→admin, `CONVOCATORIA_CREADA`→admin if pendiente else todos, `CONVOCATORIA_APROBADA`/`CERRADA`→todos (also on auto-close by cupos).
- Admin-only `/api/admin/tecnologias` CRUD: create/edit/delete technologies and their category; deleting one removes its rows from `habilidades_postulante` and `convocatorias_requisitos` in one transaction (the FK in `esquema_final.sql` is `ON DELETE CASCADE`, not RESTRICT). `GET /api/catalogos` now also returns `detalle_categorias` (`id` + `nombre`) while `categorias` stays a name list.
- Throw `HttpError(status, msg)`/`badRequest`/`conflict`/... and wrap async handlers in `asyncHandler`; `app.js` returns every error as `{ error }` and hides 5xx details. Use `conTransaccion` from `config/db.js` for multi-table writes.
- Inconsistent response shapes: `GET /api/personas` → `{ total, resultados }`; `GET /api/convocatorias` → plain array; `/ranking` → `{ convocatoria, total, total_patron, umbral, resultados[], excluidos[], contratados_detalle[] }`; `/mis-convocatorias` → array (staff must send `?persona_id=`) with `kpi_conv`, `califica`, `posicion`, `motivo_exclusion`, `estado_candidato`. `GET /api/postulaciones` and `/api/candidatos` are the same cola and only require `autenticar` — don't copy that pattern for other staff routes.
- `personas.correo` is UNIQUE (one profile row per email). `convocatorias_requisitos.nivel_minimo` is an INT FK to `catalogo_nivel_tecnologia` (NULL = sin mínimo, omitted → `basico`); unknown name/id → 400; an unknown technology is auto-created using `h.categoria` when supplied, otherwise category `otro`. That table has no `id` column (PK `(convocatoria_id, tecnologia_id)`) — never `ORDER BY cr.id`.
- KPI is calculated, never authoritative: ranking sorts by `score = kpi_conv`, profile KPI only breaks ties. Profile KPI = 5 binary checks ×20 (experiencia, formación, tecnologías, disponibilidad, algún contacto). `calcularKpi` **ignores** the `peso_*` and umbrales that `PUT /api/configuracion` still validates. KPI changes must touch `services/kpi.js`, `services/kpiConvocatoria.js`, `configuracion_kpi`, `ComoSeCalcula.jsx` and the tests together; recompute seed snapshots with `cd backend; node tools/seed-snapshots.js --print` then without `--print`.
- Registration is always `postulante`/`pendiente` with 6 fields. Current working tree also enforces password ≥8 with letters **and** numbers, names letters-only, phone ≥6 digits — validated in `utils/validar.js` and in `Registro.jsx`/`MiPerfil.jsx`. Pending users can log in but `PUT /yo` → 403 (`soloActiva`), the UI confines them to `/mi-panel` + `/mi-perfil`, and they are not in the padrón until approved.
- Preserve Spanish API field names, route names, UI text and the legacy `/vacantes*` aliases (backend router + `/vacantes` → `/convocatorias` redirect) unless explicitly renamed.

## Frontend: non-obvious rules
- One `App.jsx`, two portals. Public: `/`, `/convocatorias`, `/empresas`, `/contacto`, `/login`, `/registro` wrapped in `PublicoCorporativo`. Interno: `/interno/login`, `/interno`, `/interno/buscar`, `/interno/personas/:id`, `/interno/convocatorias`, `/interno/convocatorias/:id`, `/interno/tecnologias` (admin only, `GestionTecnologias.jsx`), `/interno/como-se-calcula` (admin only). Admin sidebar also has the `Tecnologías` link. Postulante lands on `/mis-convocatorias` (or `/mi-perfil` if pending); `/mi-panel` redirects to `/mis-convocatorias`. Sidebar comes from `enlacesDe()`; `esRutaPublica()` hides it on every public path. Public `/login` rejects staff without saving the token; `/interno/login` accepts all roles.
- CSS isolation: `PublicoCorporativo` injects `/marco.css` always but `/corporativo.css` only when `esRutaCorporativa(pathname)` is true — **not** on `/login` or `/registro`, where the corporate CSS would override Tailwind's `@layer` `.card`/`.btn`/`.input`. Both links are removed on unmount. Public cards are `ConvocatoriaCardCorporativa` + pure helpers in `lib/corporativo.js` (`separarRequisitos`, `cuposCubiertos`, `mensajeConvocatoria`, `esRutaCorporativa`).
- State is localStorage synchronized reactively via `frontend/src/context/AuthContext.jsx` + `hooks/useAuth.js` (`token`, `rol`, `correo`, `estado`, `tema`). Always use `lib/api.js` (Bearer header; auto-serializes object `body` to JSON, clears `token`/`rol`/`correo` on 401, leaves `estado_cuenta`). `guardarSesion`/`salir` dispatch `sesion-cambiada`; `AuthProvider` listens to it and `storage` to refresh state and start/stop SSE. `tema` drives `.dark` **and** `data-theme` (inline script in `index.html` avoids the flash). `ErrorBoundary` wraps `<Routes>` keyed by pathname — a blank page means a render crash; check the console.
- Realtime UI lives in `lib/realtime.js` (`EventSource /api/realtime?token=...`, 8 mapped events, `useEventoRealtime`), managed by `AuthProvider`. `Gestor.jsx` and `MiPanel.jsx`/`MisConvocatorias.jsx` reload on events. `CUENTA_APROBADA` auto-renews the session with `nuevoToken` and opens `ModalCuentaAprobada`; `CUENTA_RECHAZADA` alerts and logs out. `MiPerfil` adds unknown technologies with a category (modal), calls `invalidarCatalogos()` after saving, and rejects duplicate skill names. Admin technology CRUD also calls `invalidarCatalogos()`.
- `useCatalogos()` returns `null` on first render: initialize mapped arrays to `[]` or use `(cats.x || [])` — this exact mistake once blanked `/convocatorias`. UI holds only labels/colors in `lib/estados.js`; transitions come from `transicionesDe(catalogos, estado)`. Button actions use `hooks/useAccion.js` (`ocupado` + toast); `useToast` is in `lib/toast.js`, `<ToastProvider>` in `components/Toast.jsx`.
- Tailwind v4 is CSS-first: tokens/classes live in `src/index.css` (`@theme`, `--color-brand-*`, `.card`, `.btn-primary`, `.input`, `.tbl`, ...); `tailwind.config.js` is inert (no `@config`). Don't add classes expecting that config to be read.
