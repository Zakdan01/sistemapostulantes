# AGENTS.md

## Mapa y arranque
- Two apps, no root package/workspace: `backend/` (Express 5 + `pg`, raw SQL, CommonJS) and `frontend/` (React 19 + Vite 8 + Tailwind v4). Backend never serves the SPA: Vite proxies `/api` → `localhost:3000` in dev; `frontend/dist/` is build output only.
- Run backend **from `backend/`**: `dotenv.config()` resolves `.env` from cwd. `backend/.env` is tracked (`DB_NAME=sistemapostulantes`); `.env.example` and `src/config/db.js` fall back to `postulantes_v2`, so a missing/unread `.env` silently targets the wrong DB. Frontend has only `.env.example`; `lib/api.js` falls back to `''` → same-origin `/api`.
- No CI, hooks or root scripts; nothing auto-verifies changes. Root `.docx`/`.html`/`.png` and `generar_documentacion.py` (needs `python-docx`) are academic deliverables. `docs/superpowers/plans/` and `.superpowers/sdd/` are **completed** design history, not live docs; `frontend/README.md` is stock Vite boilerplate.
- `iniciar.bat` → `dev-runner.cjs` starts backend, then frontend 2.5 s later; `detener.bat` kills listeners on ports 3000/5173. Both servers print the LAN URLs to use; Vite prints the `Postulantes` (`/`) and `Sistema interno` (`/interno/login`) links. Never hardcode a LAN IP.
- `Silver parasoul inc/` (old static site) was intentionally removed; its design lives in `frontend/public/*.css` + `PublicoCorporativo`. Don't restore it.

One file: `node --test tests/convocatorias.test.js`; one test: add `--test-name-pattern="texto del test"`; retarget with `API_URL=http://host:port`. ## Backend: non-obvious rules
- Flow `routes → controller → service → model (SQL only) → JSON`. `src/domain/catalogos.js` is the single source of truth for roles, states, transitions, levels/factors and KPI keys; frontend reads them from `GET /api/catalogos` (**requires** a token). Role gates live only in `routes/index.js`; row-level scoping (`exigirDueno`, `creada_por`) lives in controllers.
- **No existe la postulación**: the postulante edits his profile (`PUT /yo`) and the live candidate list is recomputed from it. Old `postular`/`mis-postulaciones`/`postulaciones/:id/estado` routes are 404.
- Padrón = personas without account or `postulante` + `estado_cuenta='activa'`, with `disponibilidad <> 'Contratado'`. Cached 60 s in `services/candidatos.js`; invalidate via `Candidatos.invalidarPadron()` on profile/person/account changes, technology CRUD and hire. Clean seed: **50**.
- `convocatorias.tipo` is closed (`Pasantía|Momentáneo|Mensual|De planta`; outside → 400). `kpi_minimo` (0–100, default 25) is a listing threshold, not a hard filter: below it the person appears in `excluidos[]` with `motivo_exclusion`. `cupos` (default 1) are vacancies; the last hire closes the convocatoria in the same transaction (`SELECT ... FOR UPDATE`, `cierre_automatico: true`). `cerrada`/`rechazada` is read-only (409); `PATCH /:id` only while `pendiente`/`abierta` (admin any, reclutador own → 403 otherwise).
- Pipeline rows live in `candidatos_convocatoria`; staff creates them by **tomando** a candidate (UPSERT) and snapshots (`kpi_al_tomar`, `match_pct`, `kpi_perfil`) freeze on first take. Transitions: `postulado→consulta|descartado`, `consulta→preseleccionado|descartado`, `preseleccionado→contratado|descartado`, `descartado→consulta`; `contratado` terminal. Invalid → 409, same state → no-op. `mover` validates, locks the row, enforces cupos, appends `eventos_postulacion` (bitácora only) and runs in `conTransaccion`.
- `contratado` is per convocatoria: that ranking skips the row (it goes to `contratados_detalle[]`), other convocatorias still show the person. But hiring also sets `personas.disponibilidad='Contratado'`, removing her from **all** padrons until she saves another availability in `MiPerfil`; `GET /api/mis-convocatorias` then reports `califica:false`, `posicion:null`, «Ya estás contratado en esta convocatoria».
- Routes without `autenticar`: `/api/health`, `/api/auth/registro`, `/api/auth/login`, `/api/tecnologias`, `/api/publico/convocatorias`, `/api/realtime` (SSE verifies the JWT itself from `?token=` or Bearer; `JWT_SECRET || 'dev'`). Public listing is `abierta`-only, whitelisted fields (`id, titulo, tipo, anios_min, disponibilidad, cupos, vacantes, requisitos[]`, optional ones suffixed ` (deseable)`) — no `kpi_minimo`, correos or internal counts.
- Realtime is in-memory SSE (`services/eventosRealtime.js`, no persistence/replay); `CUENTA_APROBADA` carries `nuevoToken` with `estado_cuenta:'activa'`, approval/closure events reach all clients, registration/admin-account events reach admin or the user.
- Admin-only `/api/admin/tecnologias` CRUD; deleting a tech removes its rows from `habilidades_postulante` and `convocatorias_requisitos` in one transaction (`ON DELETE CASCADE` in `esquema_final.sql`). `GET /api/catalogos` also returns `detalle_categorias` (`id` + `nombre`); `categorias` stays a name list.
- Throw `HttpError(status, msg)`/`badRequest`/`conflict`/... and wrap async handlers in `asyncHandler`; `app.js` returns every error as `{ error }` and hides 5xx details. Use `conTransaccion` from `config/db.js` for multi-table writes.
- Response shapes are inconsistent: `GET /api/personas` → `{ total, resultados }`; `GET /api/convocatorias` → plain array; `/ranking` → `{ convocatoria, total, total_patron, umbral, resultados[], excluidos[], contratados_detalle[] }`; `/mis-convocatorias` → array (staff must send `?persona_id=`) with `kpi_conv`, `califica`, `posicion`, `motivo_exclusion`, `estado_candidato`. `GET /api/postulaciones` and `/api/candidatos` are the same cola with only `autenticar` — don't copy that pattern for other staff routes.
- `personas.correo` is UNIQUE (one profile row per email). `convocatorias_requisitos.nivel_minimo` is an INT FK to `catalogo_nivel_tecnologia` (NULL = sin mínimo, omitted → `basico`; unknown → 400); unknown tech is auto-created with `h.categoria` else `otro`. That table has no `id` column (PK `(convocatoria_id, tecnologia_id)`) — never `ORDER BY cr.id`.
- KPI is calculated, never authoritative: ranking sorts by `score = kpi_conv`; profile KPI (5 binary checks ×20: experiencia, formación, tecnologías, disponibilidad, algún contacto) only breaks ties. `calcularKpi` **ignores** the `peso_*`/umbrales that `PUT /api/configuracion` still validates. KPI changes must touch `services/kpi.js`, `services/kpiConvocatoria.js`, `configuracion_kpi`, `ComoSeCalcula.jsx` and the tests together; recompute seed snapshots with `cd backend; node tools/seed-snapshots.js --print` then without `--print`.
- Registration is always `postulante`/`pendiente` with 6 fields. Password ≥8 with letters **and** numbers, names letters-only, phone ≥6 digits — enforced in `utils/validar.js` and `Registro.jsx`/`MiPerfil.jsx`. Pending users can log in but `PUT /yo` → 403 (`soloActiva`), the UI confines them to `/mi-perfil`, and they are not in the padrón until approved.
- Preserve Spanish API field names, route names, UI text and legacy `/vacantes*` aliases (backend router + `/vacantes` → `/convocatorias` redirect) unless explicitly renamed.

## Frontend: non-obvious rules
- One `App.jsx`, two portals. Public: `/`, `/convocatorias`, `/empresas`, `/contacto`, `/login`, `/registro` wrapped in `PublicoCorporativo`. Interno: `/interno/login`, `/interno`, `/interno/buscar`, `/interno/personas/:id`, `/interno/convocatorias`, `/interno/convocatorias/:id`, `/interno/tecnologias` and `/interno/como-se-calcula` (admin only). Postulante lands on `/mis-convocatorias` (or `/mi-perfil` if pending); `/mi-panel` redirects. Sidebar comes from `enlacesDe()`; `esRutaPublica()` hides it on public paths. Public `/login` rejects staff without saving the token; `/interno/login` accepts all roles.
- CSS isolation: `PublicoCorporativo` injects `/marco.css` always but `/corporativo.css` only when `esRutaCorporativa(pathname)` — **not** on `/login` or `/registro`, where it would override Tailwind's `@layer` `.card`/`.btn`/`.input`. Both links are removed on unmount. Public cards use `ConvocatoriaCardCorporativa` + pure helpers in `lib/corporativo.js`.
- State is localStorage synchronized reactively via `context/AuthContext.jsx` + `hooks/useAuth.js` (`token`, `rol`, `correo`, `estado`, `tema`); `guardarSesion`/`salir` dispatch `sesion-cambiada`, and `AuthProvider` also listens to `storage`. Always use `lib/api.js` (Bearer header, auto-JSON object bodies, clears `token`/`rol`/`correo` on 401 but leaves `estado_cuenta`). `tema` drives `.dark` **and** `data-theme` (inline script in `index.html`). `ErrorBoundary` wraps `<Routes>` keyed by pathname — a blank page means a render crash.
- Realtime UI lives in `lib/realtime.js` (`EventSource /api/realtime?token=...`, 9 mapped events) managed by `AuthProvider`. `CUENTA_APROBADA` renews the session with `nuevoToken` and opens `ModalCuentaAprobada`; `CUENTA_RECHAZADA` alerts and logs out. `Gestor.jsx` and `MisConvocatorias.jsx` reload on events. Technology CRUD (`GestionTecnologias.jsx`, `MiPerfil.jsx`) calls `invalidarCatalogos()` after saving.
- `useCatalogos()` returns `null` on first render: initialize mapped arrays to `[]` or use `(cats.x || [])` — this exact mistake once blanked `/convocatorias`. UI holds only labels/colors in `lib/estados.js`; transitions come from `transicionesDe(catalogos, estado)`. Button actions use `hooks/useAccion.js` (`ocupado` + toast); `useToast` is in `lib/toast.js`, `<ToastProvider>` in `components/Toast.jsx`.
- Tailwind v4 is CSS-first: tokens/classes live in `src/index.css` (`@theme`, `--color-brand-*`, `.card`, `.btn-primary`, `.input`, `.tbl`); `tailwind.config.js` is inert (no `@config`). Don't add classes expecting that config to be read.
